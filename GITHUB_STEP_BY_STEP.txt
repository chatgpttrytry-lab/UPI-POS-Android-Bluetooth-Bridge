GITHUB ACTIONS APK BUILD — STEP BY STEP
========================================

A. Create a GitHub repository
1. Sign in at https://github.com
2. Tap the + icon > New repository.
3. Repository name: UPI-POS-Android-Bluetooth-Bridge
4. Choose Private (recommended) or Public.
5. Tap Create repository.

B. Upload the project files
1. Download and extract UPI_POS_Android_Bluetooth_Bridge_Project.zip.
2. Open the new repository in GitHub.
3. Choose Add file > Upload files.
4. Upload the CONTENTS of the extracted project folder, not the ZIP itself.
5. Ensure these are at the repository root:
   - app/
   - build.gradle.kts
   - settings.gradle.kts
   - gradle.properties
   - .github/workflows/android-apk.yml
6. Commit changes to the main branch.

C. Start the APK build
1. Open the repository's Actions tab.
2. Select "Build UPI POS Android APK".
3. Tap Run workflow > Run workflow.
   (A push to main also starts a build automatically.)
4. Wait until the workflow shows a green check mark.

D. Download the APK
1. Open the completed workflow run.
2. Scroll to Artifacts.
3. Download UPI-POS-debug-APK.
4. Extract the downloaded artifact ZIP to get app-debug.apk.
5. Transfer app-debug.apk to the Android phone and install it.
6. If Android asks, allow installation from that file/browser app.

E. Connect the printer
1. Pair MT580P in Android Settings > Bluetooth first.
2. Open the installed UPI POS app.
3. Open its Bluetooth Printer settings and choose the paired MT580P.
4. Set it as Default and try Test Print.

Important notes:
- The workflow builds a DEBUG APK for testing; it is not a Play Store release.
- This is an initial bridge project. APK compilation does not prove that the printer
  protocol or the app's actual invoice print path works on the MT580P.
- Test on the actual phone/printer. If the printer does not connect or print, collect
  the GitHub Actions build log and a screenshot/error message for the next fix.
- The native bridge uses Bluetooth Classic SPP/RFCOMM. A printer that uses a
  vendor-specific protocol may need its vendor SDK.
